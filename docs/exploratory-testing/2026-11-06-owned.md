# Installation exploration with registered teardown

This is a repeat of the [earlier installation pass](2026-11-06-install.md). The earlier pass did not register an exit trap before setup. This repeat registered a cleanup owner before creating its worktree or launching test processes.

## Starting state

The tap was at `d7d139d0c589abd9616e07ab2556be39ccba95be` on Linux x86_64. Homebrew 7.0.12 was checked out at `bf464f57275cae0be106b43d190c98564ac59b0e`. The Homebrew prefix, HOME, cache, temporary files, portable Ruby, and bundled dependencies were inside a detached worktree. The tap has no lockfile. Homebrew used its own locked bundle. Homebrew reported the nonstandard prefix as Tier 3.

The [owner script](evidence/2026-11-06-owned/owner-script.txt) registers an exit trap before it creates the worktree. It registers each test command's process group when launched and waits for it. No browser, server, listening port, container, image, or volume was started. The [owner log](evidence/2026-11-06-owned/owner.txt) records process group IDs and the teardown. Paths in the logs have been replaced with placeholders; terminal color and trailing whitespace were removed.

## Finding

[Issue #4](https://github.com/jonbaldie/homebrew-tap/issues/4) already tracks the tap-first trust failure. On a fresh HOME with no installed hach, `brew tap jonbaldie/tap` succeeded, but `brew install hach` exited 1 because the tap was untrusted. `brew list --versions hach` also exited 1. After untapping, switching to another fresh HOME, and tapping again, the same install failed. `brew trust jonbaldie/tap` allowed the later installations. The README's tap-first commands imply the install should succeed without that extra step. The failure leaves a new user without hach until they follow Homebrew's trust advice.

No new bugs were confirmed. Linux ARM, macOS, remote authentication, upgrades, and the standard Homebrew prefix remain unexplored. The earlier [PR #3 review](https://github.com/jonbaldie/homebrew-tap/pull/3#issuecomment-6666038825) notes the hach Linux ARM archive selection; this pass did not replay it.

## Teardown

The exit trap removed the test worktree after the commands completed. The [verification log](evidence/2026-11-06-owned/verification.txt) records that each registered process group was absent afterward. The first verification command parsed the wrong field and produced empty IDs. It was discarded and rerun with numeric ID validation; the corrected log records that intervention. The test worktree was absent after teardown. The separate documentation delivery worktree is not part of these test resources.
