# Exploratory test of Homebrew installation

The pass tested tap commit `86fd1cdfb17f8396652cc4c970194f3d8044db68` on 2026-11-06. The host was Linux x86_64. The first Homebrew checkout used the development branch at `970da0cd771488410bb97d315e7ccb5435dfa97a`. A separate replay used stable Homebrew 7.0.12 at `bf464f57275cae0be106b43d190c98564ac59b0e`. Homebrew reported a Tier 3 configuration because its prefix was inside the test worktree, not `/home/linuxbrew/.linuxbrew`. The tap has no dependency lockfile. Homebrew installed its own portable Ruby and locked bundle inside the worktree. The test used isolated HOME, cache, and temporary directories.

The initial direct installs used a symlink from the isolated Homebrew tap directory to the worktree. The tap-first replay removed that symlink and used `brew tap jonbaldie/tap` to clone the real repository. The clone matched the tested commit. The [setup details](evidence/2026-11-06-install/setup-details.txt) record the Homebrew commit. Logs replace the worktree's absolute path with `<worktree>` and remove terminal color codes and trailing whitespace.

## Confirmed finding

[Issue #4](https://github.com/jonbaldie/homebrew-tap/issues/4) records the undocumented trust requirement for the README's tap-first path. Starting with a fresh HOME, no tap trust, and no installed hach, run `brew tap jonbaldie/tap` and `brew install hach`. The expected result is an installed executable. Instead, Homebrew exits 1 and refuses to load the untrusted formula. `brew list --versions hach` finds no installation. The [fresh replay](evidence/2026-11-06-install/fresh-replay.txt) shows the failure and the successful retry after `brew trust jonbaldie/tap`. The [first real tap replay](evidence/2026-11-06-install/real-tap-replay.txt) also failed. The [developer-mode replay](evidence/2026-11-06-install/tap-replay.txt) shows the same failure after `brew developer off`, before the fresh HOME replay. A [stable release replay](evidence/2026-11-06-install/stable-replay.txt) also failed with a separate prefix and HOME. The first fully qualified install attempts reported that Homebrew trusted each formula before the setup failure shown in the [failed setup log](evidence/2026-11-06-install/install.txt). The pass did not establish how that trust changed after uninstall. The result is specific to the tested Homebrew checkout and environment; the pass did not establish when Homebrew introduced this behavior or whether other versions behave the same way.

## Environment and limits

The first attempt set `HOMEBREW_NO_INSTALL_FROM_API=1`. Homebrew reported permission denied while attempting to clone its core tap, so all three installs failed before formula installation. The [failed setup log](evidence/2026-11-06-install/install.txt) preserves that error. Removing the setting and using Homebrew's normal API resolved the setup problem. This was a test setup failure, not a tap bug.

The pass did not test macOS, Linux ARM, authentication, remote services, upgrades from older versions, or normal-prefix Homebrew. The earlier release review already noted that hach's Linux formula selects an amd64 archive on ARM in [PR #3](https://github.com/jonbaldie/homebrew-tap/pull/3#issuecomment-6666038825). No ARM installation was available to replay that observation, so it is not a confirmed finding from this pass. No other unresolved candidates were found.
